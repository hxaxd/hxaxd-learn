# 云智能体 (Cloud Agent)

把 Agent 放到云端, 需要一起处理下面这些问题。问题本身都不新, 可以组合已有的解法。

## 特征

- 行为不确定
    - 下一步做什么由模型决定, 很难提前知道会怎么做, 消耗多少资源
    - 模型的决定会变成实际操作, 做错了会影响环境
- 长时间异步执行
    - 一个任务可能跨越多次交互, 用户离线后还会继续
    - 中途可能要等工具返回, 等事件发生, 等用户回复
- 有状态
    - 继续执行需要知道之前做到了哪一步
    - 还需要保留文件和工作环境, 只有对话历史不够
- 替用户做事
    - 能做什么取决于用户给了什么权限
    - 授权有范围和期限, 用户也可能中途收回权限

## 已有解法

- 行为不确定 -> 隔离与限制
    - 不可信代码一样要运行, 但要限制它能影响的范围
        - 沙箱限制文件和网络访问, 工具调用检查权限
        - 不同用户相互隔离, 高风险操作由用户确认
    - 死循环也不新鲜, 资源消耗要有上限
        - 时间 / 轮次 / 费用设限, 子任务和重试也算在总预算里
    - 跑完不等于做对, 需要检查结果
        - 测试 / 检查环境变化 / 用户反馈
- 长时间异步执行 -> 作业调度
    - 连接断了, 任务也应该能继续
        - 任务持久化 + 队列 + 工作节点
    - 等待时可以释放暂时不用的资源
        - 保存进度, 条件满足后再恢复执行
    - 用户需要能查看和干预任务
        - 查询进度 / 暂停 / 取消 / 接管
- 有状态 -> 持久化与恢复
    - 进程退出了, 进度不能丢
        - Checkpoint + 执行日志, 已完成的步骤直接复用结果
    - 恢复进度时, 也要恢复对应的工作环境
        - 镜像固定依赖版本, 持久卷保存工作区
        - 工作区版本要与 Checkpoint 对得上
    - 本地回滚不会撤销已经发出的消息或修改的外部数据
        - 操作幂等才能安全重试, 结果不明时先查询或对账
        - 只完成了一部分, 就需要补偿处理, 或继续完成剩下的
- 替用户做事 -> 身份与权限
    - 只给完成任务所需的权限
        - 最小权限 / 短期凭证
    - 开始时有权限, 执行时未必还有
        - 执行时检查权限, 用户撤销后不能继续操作
    - 需要知道谁在替谁做什么
        - 记录用户, 执行者和使用的权限

不可信计算, 作业调度, 有状态服务和身份管理, 都有现成的经验可以用。按任务需要组合即可。

## 接续与长期职责

- 前台连接 / 执行进程 / 任务 / 工作区有各自生命周期
- 等待时保存条件, 事件到达后重新确认事实再恢复
- 长期角色保存职责, 未解除的承诺与等待对象
- 重复事件需要识别, 没有变化时继续等待可以是正确结果
- 用户干预与任务恢复都要检查当前目标, 版本与授权

## 平台治理

- 用户 / 项目 / 任务 / 执行者 / 资源 / 权限能够对应
- 配额与费用包含重试和子任务, 运行资源有清理责任
- 成果交付与临时资源回收分别确认
- 对外操作可查询可对账, 不能把本地恢复当作外部世界恢复

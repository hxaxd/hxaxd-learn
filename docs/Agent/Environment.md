# 环境

- 理想环境应该有以下特性, 我们尽可能追求

## 状态

- 稳定对象标识, 状态来源与观察时间明确
- 环境变化可以查询, 关键依赖可以恢复或重建
- 受控任务能重置, 真实使用不能完全回放时说明重建范围

- 状态显式, 无隐性知识
- 状态可读性高
- 状态一致并新鲜

## 行动

- 回执说明动作执行到哪一步, 产物与验收对应真实状态
- 同一动作的重复 / 并发 / 部分失败有明确语义
- 版本检查, 幂等与补偿由实际执行设施落实

- 修改可恢复, Checkpoint
- 执行可隔离
- 反馈可验证
- 确定性操作工具化

## Coding Agent: 天选之子

- 项目结构是优秀知识来源, 让智能体能缩小搜索空间
- 文档承载约束和操作方式
- test: 代码即可描述需求
- build / lint / 截图是优秀的反馈来源 -> LSP 是垃圾
- Git Worktree 回滚
- Sandbox 隔离

## 可练习性

- 领域资料可获得 + 动作可执行 + 条件可恢复 + 结果可评价
- 反馈可信 / 成本可承担 / 多次尝试可比较
- 编程环境同时提供代码, 运行与测试, 这些条件也可以为其他领域构建
- 测试覆盖与业务含义仍需检查, 程序能运行不等于用户需求被满足

# Agent = 独立上下文的被连续调用的 LLM + 支撑其工作的 Harness 框架 + 工作环境

## 核心

- 一次输出不等于一次行动, 环境中的实际变化需要通过工具取得证据
- 系统能力与模型能力分开看
    - 模型不变, 补充知识 / 工具 / 流程可以改善系统表现
    - 模型参数是否学会, 需要训练后的独立验证
    - 工具, 实时事实, 权限与运行环境仍然在模型外

- Agent 领域的工作是发掘模型与环境的更高效的交互方式
- 高效性的来源直接取决于模型的训练数据
- 早期工作本质上是在发掘自然语言数据中蕴含的交互模式, 称之为 Prompt Engineering
- 随着更多后天交互模式反作用于数据的影响 + 模型能力的提升, 交互模式已不是瓶颈
    - 模型是否拥有足够的对环境的对交互方式的知识为主要优化方向, 称之为 Context Engineering
- 直至今天, 长程任务的数据融于模型后训练过程, 模型倾向变成高度可定制的能力, 围绕该能力集的完整设计标准, 称之为 Harness Engineering
- 评估驱动
- 足够复杂的任务才能使 Harness 本身更慢地被模型内化, 同时积累可用于训练的数据
    - 不然不就是传统 NLP 嘛
- 扩大观察范围与行动范围是改进 Agent 的最直观方法
- 设计原则: 简单 + 透明 + 优秀的 ACI (代理计算机接口)

## 组成

- 从模型交互看, Agent = LLM + 上下文 + 工具
    - 近似对应 RL 中的 Policy + Observation Space + Action Space

### Model

- 模型决定可被激活的能力上限
- API 协议与服务决定调用方式和成本控制

### Harness

- Harness 是模型与环境交互的中介, 建立在环境的可解析性与模型的先验能力之上
- Harness 负责维护若干个模型状态 (Context), 也负责与环境的接口 (Runtime), 以及 Harness 自身的进化 (Evolution)
- Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正
    - 纠正包括自动重试, 人工介入, 回滚

#### Context

- [Context](Context.md): Knowledge + Objective + Observation + Feedback + Cognitive Control + Action
    - 维护模型当前理解的任务与环境, 组织推理, 规划与上下文管理

#### Runtime

- Runtime 是 Action 与环境状态转变的接口, 也负责将环境状态转换为 Observation
    - 安全机制
    - 可观测性与评估机制
    - Hooks

#### Evolution

- Evolution 专指 Harness 根据交互经验对自身进行持久化修改的机制
    - 不包括 Agent 在当前 Context 中自然发生的认知更新
    - 不包括 Model 权重的训练与更新
    - 提供 Knowledge, 包括 MEMORY 和 SKILL
    - 调整 Cognitive Control, 包括 WORKFLOW
    - 优化 Runtime, 包括安全机制和可观测性与评估机制

### Environment

- 同一个智能体在不同环境中的表现可能完全不同
- 状态 + 可观测性 + 可执行动作 + 状态转移

### Human

- 意图 + 交互 + 反馈

## 能力改进

- 真实需求 -> 任务 + 环境 + 工具 + 验证器 -> 基线 -> 失败归因 -> 修改 -> 复测
- 知识 / 经验 / 流程 / 工具
    - 知识: 事实与关系, 保留来源
    - 经验: 情境与判断, 保留适用条件
    - 流程: 方法与依赖, 保留现场调整空间
    - 工具: 已验证的动作, 输入输出与失败含义明确
- 真实使用回流
    - 失败 -> 回归任务 -> Harness 改进
    - 示范 / 纠正 / 有效轨迹 -> 验证与筛选 -> 训练材料
    - 日志增加不等于经验积累, 经验必须被整理并参与下一轮工作
- 更强模型 -> 重看 Harness
    - 重新验证哪些提醒与补偿还需要
    - 新任务与新环境会带来新的能力缺口
- 递归自我改进
    - 获得的能力继续用于出题 / 评判 / 改进
    - 多轮收益, 旧能力保持, 成本与人工投入都需要检验
    - 流程接通是工程条件, 不能单独证明持续自主改进

## 基础设施

- 任务 + 上下文 + 工具 + 环境 + 产物 + 证据之间的关系应该可查询可交接
- 更换模型 / 工作流 / 执行者后, 任务含义与执行证据仍然能对应
- 工作入口统一, 具体实现按场景选择
- 生命周期 / 调度 / 资源 / 授权 / 状态 / 验证有明确责任
- 开发, 真实使用与评估可以复用设施, 各自的任务与授权边界仍需明确

# Evolution(演化)

- 演化需要先划清持久变化的边界, 再说明信号如何进入记忆和技能, 如何作用于 Harness 以及如何验证和回退这些变化

## 边界

- 当前上下文中的认知变化, Harness 持久修改和模型训练属于三种不同时间尺度, 必须先划清

- Evolution 专指 Harness 根据交互经验对自身进行持久化修改的机制
    - Agent 在当前 Context 中对 Belief, Plan 和行动倾向的更新不是 Evolution
    - Model 权重的训练与更新也不属于 Harness Evolution
- Harness Evolution 的对象
    - 改变未来提供给模型的 Knowledge, 包括 Memory 和 Skill
    - 改变未来使用的 Cognitive Control, 包括 Workflow
    - 改变 Runtime, 包括工具, 安全机制, Hooks 和可观测性与评估机制

## 信号

- 没有可比较的改进依据, 持久化只会积累偶然经验和错误模式

### Feedback(反馈)

- 具体交互中的纠正提供局部改进线索, 但通常仍带有场景依赖

### Evaluation(评测)

- 评测把局部反馈转成可比较标准, 用于决定哪些变化值得保留

- Evaluation 为 Harness Evolution 提供选择信号
    - 只有能够区分有效与无效经验, Harness 才能决定沉淀, 修改或遗忘什么

## Memory(记忆)

- 记忆保存跨交互仍有价值的事实和经验, 它是演化最直接的知识载体

### Scope(范围)

- 会话状态, 缓存和长期记忆寿命不同, 首先要限定什么值得跨交互保存

- 广义的 Memory, 包括环境信息, 用户信息与沉淀经验
    - 环境信息可验证可推导
    - 用户信息不可验证不可推导, 但对完成任务很重要
    - 沉淀经验是之前完成过的任务的总结, 包括成功的经验和失败的教训
- 关键点
    - 结构: 文本 / 知识图谱 / 结构化数据
    - 语义: 用户信息 / 沉淀经验 / 环境信息
    - 召回方式: 注入 / 检索 / 渐进式披露 / Agent 主动预测 + 推送
    - 生命周期管理: 什么时候写入 / 遗忘

### Semantics(语义)

- 事实, 偏好和经验的可验证性不同, 其写入与冲突策略不能共用

#### Environment(环境)

- 环境事实通常可重新验证, 应避免把可查询事实固化成不可质疑记忆

- 环境信息
    - 也就是工作的项目的信息, 简化模型的探索过程
    - 应该只存索引, 由模型去确定并获取事实, 避免过度依赖记忆

#### User(用户)

- 用户偏好难从环境推导却直接影响任务选择, 需要独立可信来源

- 用户信息
    - 环境中无法推断, 但对完成任务很重要的信息, 例如用户的偏好, 项目的隐式约束

#### Experience(经验)

- 成功和失败轨迹可抽象为未来策略, 但不能与客观事实使用同一置信规则

- 沉淀经验
    - 之前完成过的任务的总结, 包括成功的经验和失败的教训
    - 总结为可复用的技能, 供未来类似任务调用

### Structure(结构)

- 存储表示决定信息能否被维护和取回, 不能只讨论语义不讨论载体

- 用户信息, 项目信息, 目录信息, 本地信息等记忆分层文件存储
    - 用一个 MEMORY.md 存有语义的记忆文件索引用作渐进式披露
    - 根据工作目录动态加载并主动注入
- 对于更广阔具体的信息, 可以考虑检索 (向量相似度 / BM25 / `grep`+`read`)
- 信息最好渐进式披露

### Write(写入)

- 错误写入会长期影响未来任务, 写入条件比读取更需要严格控制

- 可以由用户主动提供, 也可以由 Agent 维护

### Recall(召回)

- 保存的信息只有在正确时机进入任务才有价值, 召回是记忆与当前上下文的接口

- 注入
    - 适合重要的, 需要模型持续关注的信息
    - 有的人也喜欢每次固定 RAG 一些环境信息, 但感觉不如让模型自己决定什么时候需要
- 检索
    - 适合大量的, 需要模型偶尔参考的信息
    - 可以包装成一个工具, 让模型决定什么时候需要调用
- 渐进式披露
    - 适合绝大部分情况其实, 而且与注入和检索不冲突
    - 提供一个索引, 需要时加载全量信息
- Agent 主动预测 + 推送

### Lifecycle(生命周期)

- 长期信息会过时, 冲突和膨胀, 必须有更新, 合并和遗忘机制

- Agent 写入时机
    - Turn 结束时
    - 失败 / 成功时
    - 定时写入
    - 压缩时
- 遗忘时机
    - 过时遗忘: 给记忆打上时间戳
    - 冲突遗忘: 记忆之间存在强相关, 遗忘或融合

## Skills(技能)

- 有些经验不仅是信息, 还包含可执行流程和资源, 因而不能只作为记忆文本

- 完整上下文, 利于 subagent
- 人类可读, 可编辑, 可审计, 可测试
- 易于分发
- Prompt 的快捷键
- Claude Code 有一个 Commands 功能, 允许 SKills 里嵌入脚本加载时处理 Skills 本身

### Knowledge(知识)

- 技能仍需要最小领域知识说明何时适用, 但不应复制完整记忆库

### Workflow(工作流)

- 可复用能力的核心是稳定步骤和决策点, 不只是静态说明

### Scripts(脚本)

- 确定性处理交给脚本能降低模型成本和随机性, 因而是技能的重要组成

### Progressive Disclosure(渐进式披露)

- 技能内容可能很大而使用频率很低, 分层加载用于控制上下文占用

## 优化

- 沉淀经验最终要落到可修改的 Harness 表面, 才能真正改变未来行为

### Instructions(指令)

- 许多稳定偏差来自指令表达, 调整指令是成本最低的持久改进面

### Workflow(工作流)

- 问题若来自步骤组织而非单句指令, 就需要修改工作流结构

### Tools(工具)

- 能力缺口有时无法靠提示补偿, 必须改变可用动作和工具契约

### Runtime(运行时)

- 重试, 安全和状态等确定性行为属于运行时, 不应让模型自行学习替代

## 治理

- 自动改进也可能退化或污染系统, 因而每次持久变更都需要可验证和可回退

### Version(版本)

- 没有版本身份就无法知道哪次改动导致行为变化

### Validation(验证)

- 新经验在局部有效不代表整体改进, 持久化前必须经过独立验证

### Rollback(回退)

- 自动演化可能产生隐性退化, 回退是允许系统持续试验的安全基础

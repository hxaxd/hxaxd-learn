# Evolution

## 边界

- Evolution 专指 Harness 根据交互经验对自身进行持久化修改的机制
    - Agent 在当前 Context 中对 Belief, Plan 和行动倾向的更新不是 Evolution
    - Model 权重的训练与更新也不属于 Harness Evolution
- Harness Evolution 通过外部制品更新改变以下对象
    - 改变未来提供给模型的 Knowledge, 包括 Memory 和 Skill
    - 改变未来使用的 Cognitive Control, 包括 Workflow
    - 改变 Runtime, 包括工具, 安全机制, Hooks 和可观测性与评估机制

## 信号

### Feedback

- 具体交互中的纠正提供局部改进线索, 但带有场景依赖

### Evaluation

- Evaluation 为 Harness Evolution 提供选择信号
    - 只有能够区分有效与无效经验, Harness 才能决定沉淀, 修改或遗忘什么

## 更新与验证

- 固定任务 / 环境 / 标准 -> 基线 -> 候选修改 -> 复测 -> 采纳 / 回退 / 继续调查
- 成功只产生候选, 适用条件与泛化收益决定能否留下
- 检查原问题 / 相邻任务 / 旧能力保持 / 耗时与成本
- 归因可能错误, 修改者需要原始证据与进入环境的调查路径
- 环境或标准有缺陷时先修设施, 再用一致条件重建比较

- 版本化
- 对账
- 自动化
- 人类可审计

## Memory

### 范围

- 广义的 Memory, 包括环境信息, 用户信息与沉淀经验
    - 环境信息可验证可推导
    - 用户信息不可验证不可推导, 但对完成任务很重要
    - 沉淀经验是之前完成过的任务的总结, 包括成功的经验和失败的教训
- 关键点
    - 结构: 文本 / 知识图谱 / 结构化数据
    - 语义: 用户信息 / 沉淀经验 / 环境信息
    - 召回方式: 注入 / 检索 / 渐进式披露 / Agent 主动预测 + 推送
    - 生命周期管理: 什么时候写入 / 遗忘

### 语义

- 环境信息
    - 也就是工作的项目的信息, 简化模型的探索过程
    - 应该只存索引, 由模型去确定并获取事实, 避免过度依赖记忆
- 用户信息
    - 环境中无法推断, 但对完成任务很重要的信息, 例如用户的偏好, 项目的隐式约束
    - 基础会议 -> 信息记住
    - 多会话检索 -> 隐式信息与依赖关系
    - 主动服务
- 沉淀经验
    - 之前完成过的任务的总结, 包括成功的经验和失败的教训
    - 总结为可复用的技能, 供未来类似任务调用
- 认知科学对长期记忆的分类
    - 情景记忆 -> 经验
    - 语义记忆 -> 知识
    - 程序记忆 -> 流程

### 结构

- 组织形式
    - 短事实
    - 整段叙事
    - JSON
    - Advanced JSON Cards: 为什么存, 为谁存
- 用户信息, 项目信息, 目录信息, 本地信息等记忆分层文件存储
    - 用一个 MEMORY.md 存有语义的记忆文件索引用作渐进式披露
    - 根据工作目录动态加载并主动注入
- 对于更广阔具体的信息, 可以考虑检索 (向量相似度 / BM25 / `grep`+`read`)
- 信息最好渐进式披露

### 写入

- 可以由用户主动提供, 也可以由 Agent 维护

### 召回

- 注入
    - 适合重要的, 需要模型持续关注的信息
    - 有的人也喜欢每次固定 RAG 一些环境信息, 但感觉不如让模型自己决定什么时候需要
- 检索
    - 适合大量的, 需要模型偶尔参考的信息
    - 可以包装成一个工具, 让模型决定什么时候需要调用
- 渐进式披露
    - 适合绝大部分情况其实, 而且与注入和检索不冲突
    - 提供一个索引, 需要时加载全量信息
- Agent 主动预测 + 推送

### 生命周期

- 事实的新鲜度, 经验的适用范围与方法的依赖分别维护
- 只保留完整聊天记录, 仍然需要重新辨别试探 / 误解 / 可迁移经验
- 事实变化时回到源数据, 用户偏好与隐式约束可以向用户核实

- Agent 写入时机
    - Turn 结束时
    - 失败 / 成功时
    - 定时写入
    - 压缩时
- 遗忘时机
    - 过时遗忘: 给记忆打上时间戳
    - 冲突遗忘: 记忆之间存在强相关, 遗忘或融合

## Skills

- 知识 + 经验 + 流程 + 工具围绕一份工作组织
- 入口说明适用条件与完成标准, 参考 / 案例 / 模板 / 脚本分别保存
- 技能边界围绕可判断收益的工作片段
- 精确且反复执行的动作可以程序化, 现场判断保留灵活性
- 读入技能改变当前上下文, 持久修改改变未来工作条件

- 完整表达知识 / 经验 / 工具 / 流程
- 完整上下文, 利于 subagent
- 人类可读, 可编辑, 可审计, 可测试
- 易于分发
- Claude Code 有一个 Commands 功能, 允许 SKills 里嵌入脚本加载时处理 Skills 本身

## 技能库

- 轨迹 -> 提炼 -> 候选 -> 试用 -> 入库 -> 召回 -> 修改 / 合并 / 拆分 / 停用
- 适用条件不能在提炼时丢失
    - 重复导入先确认批次证据, 相同行可能是真实业务
- 检索找候选, 适用条件判断能否使用
- 重复方法合并, 相反前提保留独立入口
- 接口 / 业务 / 模型改变后重新检查依赖与收益
- 调用少不等于无价值, 罕见重要任务仍需保留覆盖
- 评估整个任务流
    - 空库 / 固定库 / 动态库
    - 成功率 / 耗时 / 迁移 / 旧能力保持 / 维护成本
    - 移除或停用后的变化比文件数量更能说明作用

## 任务与评判的改进

- 任务合成: 需求 + 已有任务 + 失败 -> 候选挑战 -> 有效性审核 -> 试跑 -> 入集
    - 保留来源 / 新覆盖 / 设计理由, 参考解与执行者输入分开
    - 不可解或无用的题不能因为使求解者失败就算成功
- 评判校准: 标准 + 同一证据 -> 多次判断 -> 分歧调查 -> 修订 -> 对照检查
    - 抽检分歧案例, 也抽检没有分歧的案例
    - 人类判断同样需要理由与证据
- 求解 / 出题 / 评判 / 修改可以由不同模型承担, 分别接受质量验证

## 训练回流

- 外部经验先通过任务验证, 再整理为模型可学习的材料
- 轨迹保留当时可用的观察 / 动作 / 返回 / 专家纠正
- 不加入行动时尚不可知的证据, 不只保留最终答案
- 验证 / 筛选 / 去重 / 版本记录 / 转换格式
- 领域资料 -> 中间训练; 示范 -> SFT; 比较 -> 偏好优化; 环境与奖励 -> RL
- 外部更新与模型训练各有节奏, 训练收益需要独立验证

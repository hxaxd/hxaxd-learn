# Human

## 意图

- Goal: 目标状态
- Constraint: 不可接受的状态或行为
- Completion Criteria: 判断目标已完成所需的证据

### Spec 表达目标状态

- openspec
- spec-kit

## 交互

- 缺乏在长任务当中不断的显示进度与状态, 使人类进行引导澄清
- 模型主动提问意愿不高

## 反馈

- 缺乏反馈转化机制 -> 重新做 / 记住

## superpowers skills

### 原理

- 用 SPEC 交代意图
- 主动要求澄清 / 批准
- 零上下文计划
- 自动对抗式审查

### 流程

- 入口 -> 定义基本约束 + 流程
- 头脑风暴 -> 架构
    - 目标, 约束, 成功标准
    - 通过提问一次澄清一个细节
- 计划 -> 零上下文工程师可执行的任务分解
    - 不要重复
    - 不做多余的工作
    - TDD
- TDD
    - 红: 失败的测试用例
    - 绿: 通过测试用例
    - 重构: 优化代码, 不改变功能
- 执行
    - 自主设定 checkpoint, 要求人类审查
- ReView
    - 左移: 尽可能早地发现问题
    - 细粒度: 每个最小化 Task 都需要 Review
    - 必须提供完整上下文
    - SOLID 原则
- 收到 ReView 反馈后
    - 不能因为配合而全盘接受 ReView 结果 (例如过度设计 / 删除向后兼容)
    - 先验证后执行
    - 敢于反驳
    - 与 ReView 人员完全澄清, 而不是部分接受
- DeBug
    - 根因调查 -> 模式分析 -> 假设验证 -> 修复
    - 三次失败直接放弃, 质疑架构问题

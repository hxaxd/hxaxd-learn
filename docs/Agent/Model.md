# Model

## 能力

### 世界知识与语义理解

- 大规模预训练

### Instruction Following

- Harness 依靠指令激活行为, 指令遵循是其他智能体能力可控的前提
- 包括风格调整

### Reasoning

- 复杂任务需要在行动前组合证据和推导后果

### Tool Use

- 把意图转换为结构化外部动作
- 包括计算机操作

### Structured Output

- 下游系统需要机器可解析结果, 仅靠自然语言约定无法形成稳定接口

### Long Context

- 可同时处理的信息规模直接限制长任务的连续性和证据覆盖

### Multimodal

- 环境信息不只存在于文本, 图像和音频需要不同的感知能力

### 推理深度

- 对特定上下文的反应 `Reasoning: Low`

### Agentic

- 长程任务
- 计划
- 反思

## API 协议与服务

- 最早是聊天补全接口, 给个消息, 返回个消息, 但随着能力的增加, 需要更多参数和控制
- Response API 与应用的接口消息是结构化的, 会被序列化为文本
    - system: 可以打点限制稳定前缀
    - developer
    - user
    - assistant
    - tool_result
    - 推理状态
    - ... 其实你在对话中看见的框框大抵对应一种对象
- 大部分情况我们都是追加内容
    - 指定 previous_response_id 并追加

### 工具调用

- API 直接返回工具调用, 而不是文本
    - 帮你校验结构, 但是语义不一定
    - 工具调用与结果返回都是结构化的, 靠 id 对应
- 为了实现缓存
    - 工具列表尽量不变
    - 启动工具每次声明并注入
- 云端工具与本地工具
    - 云端工具不一定会把结果立刻给你, 可能会异步返回

### 压缩

- API 直接提供上下文压缩
    - 可以设定触发时上下文大小
    - 禁止工具调用
    - 保留一部分上下文, 一部分做摘要
    - 摘要作为一个对象, 可见但不可查看内容
    - 可以提供指令

### 参数

- 温度: 控制随机性
- 最大输出 token
- 推理深度: 注入提示词
- 结构化输出: 提示词设计 + 限制选词空间 + 后校验 / 处理

### Cache

- KV-Cache 特指一次推理中模型内部的注意力缓存, 由推理服务维护
- 语义缓存: 模型输入的语义级别缓存 (向量化), 直接存答案

#### Prompt Cache

- 重复前缀可直接复用 KV-Cache
- 可显式创建
- 自动创建是根据长度递进的

### 流式输出

- 中间穿插工具调用
- SSE 或者 WebSocket

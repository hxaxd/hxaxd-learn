# Retrieval

## 边界

- 检索作为工具调用的一种, 不应独立强调, 但目前领域中对 RAG 的关注度过高, 故单独列出
- RAG (检索增强生成)
    - 狭义上指数据预处理 -> 切块 -> 向量化 -> VectorDB -> 对提问向量化 -> 相似度匹配 -> 重排序 -> 注入上下文

## 数据预处理

- 检索质量由从原始数据到最终上下文的整条链共同决定, 但是数据的结构性和语义完整性尤其重要
- 格式转换
    - 能不转换就不转换, 直接从数据源获取结构化信息
    - 超文本格式易于解析为结构化内容, 例如 MD
    - 多模态内容考虑标签化, 或者使用多模态嵌入模型

## 表示与向量化

- 如何表示决定如何索引, 检索与召回
- 索引
    - 倒排索引 -> BM25
    - 向量索引 -> HNSW, IVF, PQ
    - 图索引 -> 知识图谱
- 索引背后一定是真实源数据
    - 最好带获取源数据的方式, 例如 URL, 文件路径, 数据库主键
    - 带上一堆拓展数据
- 知识图谱 (本质垃圾)
    - 编译知识大于检索知识
    - 不一定是用向量检索节点, 也可能是 LLM Wiki

### 切块

- 带结构的东西即使分的再好, 原子信息依旧可能过大, 切块不可避免
- 直接切 / 考虑标点
- 切块时塞进去一些有索引意义的上下文, 例如标题, 章节号, 文件名, LLM 总结
- 甚至叫 Agent 直接帮你切块

### 向量化

- 向量化模型将输入映射到高维空间, 使得语义相似的输入在向量空间中距离更近
- 存在多模态嵌入
- 降低模型输出维度的方法
    - 截断 + L2 归一化
    - 计算样本的协方差矩阵 (PCA)
    - 对输出截取奇异向量 (SVD)
    - 模型提供学习到的投影头

## 向量数据库与索引

- 稠密表示需要专门系统完成近邻查询和规模化维护, 其工程问题不同于检索策略
- Distance(距离): 向量只有通过距离函数才产生相似度顺序, 不同度量会改变召回语义
- Index(索引): 精确遍历无法支撑大规模低延迟查询, 索引负责在速度和召回率间取舍
    - Flat(扁平索引): 精确遍历提供召回率上限和小规模基线, 用于衡量近似索引损失
    - IVF(倒排文件索引): 先按聚类缩小搜索空间适合大规模查询, 但会引入分桶边界损失
    - HNSW(分层可导航小世界图): 图导航以较高内存换取低延迟和高召回, 代表另一类核心取舍
    - PQ(乘积量化): 向量压缩能显著降低内存和带宽, 代价是距离估计误差
- Filter(过滤): 语义相似并不保证租户, 时间和权限正确, 结构化过滤必须参与查询
- Update(更新): 知识持续变化, 索引的新鲜度和删除语义会直接影响事实正确性
- Distribution(分布式处理): 单机容量和吞吐存在上限, 分片与副本又会引入一致性和路由问题

## 召回

### 预处理

- 查询改写, 补全实体, 消除歧义和匹配索引语言
- 重写为多角度的多个查询
- 生成假回答进行检索
- 也考虑多跳检索, 尤其在知识图谱中

### 后处理

- 多路召回产生不可直接比较的分数和排名, 融合负责形成统一候选序列
- 召回的候选集可能包含大量噪声, 需要模型或规则重新排序
    - 重排序模型直接输入查询与候选集, 输出相关性分数

## 知识图谱

- 关系密集问题依赖实体间路径而非单点相似度, 因而形成专门的图检索分支
- LightRAG
    - 构建
        - llm-based 提取 chunk 中实体与关系为 K-V 形式 (实体名 - 实体摘要 / 实体暗示的全局主题 - 关系内容)
        - 对所有实体 / 关系的 K-V Embedding, 存入 VectorDB, 构建为知识图谱
        - 投入新文档不需要重新构建
    - 检索
        - llm-based 提取 Prompt 中实体与抽象
        - 实体向量检索实体, 再根据图谱关系做二跳检索
        - 抽象向量检索关系, 获取相关实体

### 代码检索

- AST
    - 对代码的最佳分析方式
    - 使用 Tree-sitter
- Semble
    - 对代码进行 RAG, 提供一个声明式的代码检索工具
    - 模型仅需要声明式地描述需要检索什么代码
    - 自称相较于 grep+read 节省 98% 的 Token
- CodeGraph
    - 把代码建立为知识图谱, 包括符号关系, 调用图和代码结构
    - 支持自动同步, 识别部分 WEB 框架的隐式调用关系
    - 存在 SOLite, 支持全文搜索
    - 支持影响分析, 避免 Agent 漏修改

## Evaluation

- 召回: 召回的相关信息占总相关信息的比例,
- 精确率: 召回的相关信息占总召回信息的比例
- Hit Rate: 召回的相关信息是否至少有一个
- MRR: 第一个相关结果的倒数排名, 关注最优结果
- nDCG: 归一化折损累积增益, 相关性 + 排名

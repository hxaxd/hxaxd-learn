# 多智能体

## 边界

- 多智能体带来的协调成本很高, 必须先判断是否真的超过单智能体能力
- 任务正交 / 可并行 / 使用子集能力 / 阶段性隔离上下文

## 形态

- 顺序: 后一步依赖前一步结果时, 顺序拓扑能保持因果关系并压缩上下文
- 并行: 独立子问题可并行增加视角, 但需要结果合并
    - 增强鲁棒性, 但需要解决冲突
    - 可从多角度探索问题
- 层级: 大任务需要集中分解和监督时, 层级结构明确责任和汇报路径
- 对等: 没有稳定主控者的协作需要成员平等协商
- 对抗: 用两个完全相反的视角看待同一个解决方案
- Dynamic Graph: 依赖关系可能在执行中才出现, 动态图允许拓扑随任务状态变化

### Subagent

- 子智能体由主智能体控制且上下文隔离, 适合有明确输入输出的局部任务
- 只能主从交流, 本质是声明式的工具调用
- 也是一种压缩方式
- 可恢复可嵌套

## 机制

- 隔离: 独立的身份, 权限, 工作区, 上下文, 记忆
- 通信:
    - Message: 直接消息, 一般不咋地
    - Mailbox: 互相写邮箱文件
    - 黑板: 共享黑板允许成员依据当前状态异步认领工作
    - A2A 不属于该类, 本质上是提供 Agent 服务的发现 / 任务状态维护 / 消息与结果传递
- 每个成员都需要有生命周期
    - Leader 管理 team config
    - 关机必须经过: 请求 -> 拒绝 / 同意并首尾 -> 确认关机 -> 通知团队并更新 team config
    - 所有消息传递与工作调度都依赖邮箱 + 轮询实现

# 深入理解 Agent

## 研究什么

- 评估驱动
- 足够复杂的任务才能使 Harness 本身更慢的被模型内化, 同时积累可用于训练的数据
    - 不然不就是传统 NLP 嘛
- Agent = LLM + 上下文 + 工具
    - 近似对应 RL 中的 Policy + Observation Space + Action Space
- 扩大观察范围与行动范围使进化 Agent 的最直观方法
- 设计原则: 简单 + 透明 + 优秀的 ACI (代理计算机接口)
- 设计模式
    - 提议者 / 审核者
    - 渐进式披露
    - 只增不改 -> KV-cache
    - 边界集 + 保留集 -> 评估
    - 最小 diff + 可回滚

## 工具

- 通用基础能力用于组合与探索, 专用工具用于约束高风险和强业务规则操作
- 工具定义中强调使用边界 + 示例 + 性能 + 工具间协作
- 也可以渐进式加载

## LLM

- 推理时计算
- 模型既 Agent -> Harnees 的能力随轨迹内化进模型 (苦涩的教训)
- 注意力分配中发现的模式
    - 模型会把多余注意力给序列的第一个 Token
    - 首尾上下文更容易被注意
    - 思考时频繁回看之前的内容
    - 输出时频繁回看思考的内容
- Chat Template 负责序列化上下文
- 结构化输出依赖约束解码
- 一大堆参数主要就是
    - 选词空间
    - 输出数量
    - 思考强度

## 进化

- 任务内适应
- 外部制品更新

## 上下文

- 包括系统提示词 + 工具定义 + 用户消息 + 模型回复 + 工具执行结果

## Harness = 上下文管理 + 工具接口 + 约束 + 验证 + 纠正

- 纠正包括自动重试, 人工介入, 回滚
- Agent 状态栏在上下文末尾注入动态的元信息
    - 注意力倾斜非常明显且几乎完全相信

## 工作流

- 单次调用 -> Workflow (安全稳定) -> Agent (变通)

## 护栏

- 上下文层
    - 打上来源标记 + 限制外部信息的角色
    - 相关性分类器拦截无关输入
    - 安全分类器拦截危险输入
    - 实现方法为内容审计与基于规则的保护
- Anthropic 的 Constitutional Classifiers5
    - 用自然语言写成的规则生成合成训练数据, 训练输入输出分类器
    - 上下文联合判断, 把用户提问和模型回答放在一起检查
    - 两级筛查, 先用轻量探针检查所有对话发现可疑之处再交给更强的分类器复审
- 执行层与数据层更稳定重要
    - 尤其执行层中的输出层
- 超过失败阈值 / 高风险 -> Human in the Loop

## RAG

### 稠密嵌入

- 把文本转为向量, 以便在向量空间中进行相似性搜索
- 向量索引
    - ANNOY 基于树, 快, 内存占用低
    - HNSW 基于图, 可增量插入, 但会降低精度

### 稀疏嵌入

- 词袋模型仅记录词在文档中出现的频率
- 检索
    - TF-IDF 计算词频和逆文档频率, 但长文本易被高分
    - BM25 改进了 TF-IDF, 通过考虑文档长度和词频饱和度来提高检索效果

### 多路召回

- RRF: 1/(k + rank) 的和
- 重排
- 指标
    - recall: 检索到的相关文档占所有相关文档的比例
    - MRR: 平均倒数排名, 计算相关文档在检索结果中的平均排名的倒数
    - nDCG: 归一化折损累积增益, 考虑相关文档的排名和相关性得分

### 索引

- 树状索引与知识图谱
- 文件系统与 LLM Wiki
- 写入门控与定期整理

## 评估

- 可观测性 + 内部评估基础设施 + 仿真
- 成功的定义
    - Pass@k 执行 k 次, 至少有一次成功 -> Best@k
    - Pass^k 执行 k 次, 全部成功
- 任务来源
    - 公开基准
    - 自建业务集
    - 生产轨迹回流
- 验证方式
    - 确定性
    - 检查项
    - 评分标准 + LLM
    - 配对比较 (小心位置偏差)
- 结果的运用: 统计显著性 -> 失败归因 -> 回归任务 -> 迭代优化

- 评分标准的设计
    - 基于专家指导
    - 全面覆盖
    - 按重要性加权
    - 评价标准客观可验证
- 古德哈特定律 -> 当指标成为目标时, 它就不再是一个好的指标
    - 多源异构评判

- 归因第一个错误

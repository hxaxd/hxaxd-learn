## 概念

- OLTP: 在线事务处理, 主要是数据库的增删改查
- OLAP: 在线分析处理, 主要是数据仓库的分析查询
- ETL: 抽取 -> 转换清洗 -> 加载到数据仓库
    - 架构稳定, 接口统一
- ELT: 抽取 -> 加载到仓库 -> 转换清洗 / DAG 建模 (用 dbt 建模, 本质 SQL)
    - 数仓 / 湖仓很便宜, 直接放进来慢慢加工
    - 可重放
- Lambda: 批处理 + 流处理同时
- Kappa: 只保留流处理, 批处理从流重放

## 数据来源

### 业务数据库

- 问题是数据库服务在线业务, 不应该被分析任务直接拖慢, 所以通过备份, 主从库, CDC 或数据同步工具把数据复制出来
    - 早期做法是定时导出 (导出不原子)
    - CDC: 监听数据库变更日志, 将插入, 更新, 删除转换成事件流

### 行为事件

- 应用埋点, 直接上报行为事件
    - 全局唯一的 `event_id` (防止重复)
    - 事件发生时间 `event_time` (防止乱序)

### 文件和外部数据

- 非结构化 / 结构多变
    - 先接入进湖, 再清洗成结构化表

## 采集与接入

- 目标: 完整, 可重放, 可追踪
- 使用一些采集框架, 不重要
- 批量同步
    - 延迟太高
    - 出错后需要重跑整个分区
- 消息队列
    - 生产者写入 topic, 消费者按自己的进度读取
    - 可重放, 可追踪, 可扩展

## 存储

- 原始层: 保存最接近数据源的数据
    - 要求完整和可重放
    - 一般就是用分布式文件系统或对象存储, 按时间分区存储
- 清洗层: 原始数据 -> 结构稳定的数据
    - 还是存在文件系统里, 但按表分区存储
- 建模层: 组织成表
    - OLAP: 满足分析查询
    - OLTP: 满足事务查询
    - 存储在分布式列式数据库
- 实时存储: 满足低延迟查询

### 组件

- 数据仓库
    - 分布式列式数据库 (ClickHouse)
- 数据湖
    - 分布式文件系统 / 对象存储
- 湖仓
    - 数据湖 + 建立湖上元数据

## 转换与建模

- MapReduce
    - Map 把数据拆开并产生中间键值
    - Shuffle 按 key 分组
    - Reduce 阶段聚合
- Spark
    - DataFrame / SQL 表达结构化计算
    - 内存计算改善迭代任务
    - 本质就是 MapReduce 的更高层次的抽象
- Flink
    - 有状态流式计算
    - 解决事件时间, 乱序, 迟到, 状态管理
- 维度建模 (dbt)
    - 把数据组织成事实表和维度表
    - 事实表: 发生了什么
    - 维度表: 从哪些角度看事实
- 特征建模

## 服务与消费

- BI
- 实时看板
- 在线服务
    - 低延迟缓存层
- 训练与实验
    - 可回放的历史数据
    - 防止数据穿越: 使用了预测时不可能知道的未来信息

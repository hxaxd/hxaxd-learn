## 主张驱动的实验规划

先建立对应关系:

```text
论文主张 -> 所需证据 -> 实验协议 -> 图表 -> 允许写入的结论
```

示例:

| 主张 | 实验 |
|---|---|
| 总体效果更好 | 与强基线进行公平对比 |
| 模块一解决目标问题 | 移除或替换模块一 |
| 两个模块需要共同工作 | 单独启用和联合启用 |
| 方法对输入噪声更稳定 | 多档噪声压力测试 |
| 方法更高效 | 相同硬件和输入下测试时间, 显存和存储 |

## 对比实验

### 已有直接基线

- 选择相关且较新的强方法
- 统一数据集划分和预处理
- 统一训练信息或明确说明采用公开结果
- 同时报告任务质量, 效率和资源等重要指标
- 指标标题标明数值增大或减小代表更好

![对比实验表示例](../images/对比实验表示例.png)

### 新任务没有直接基线

可以构造:

- 现有方法到新任务的合理适配版本
- 移除核心新设计的方法变体
- 使用通用模块替换新模块的版本
- 简单但有意义的启发式方法

这些变体需要说明设计理由, 不能故意构造过弱对手

## 消融实验

### 核心贡献总表

使用一个总表展示主要模块和设计选择对完整方法的影响

![消融实验总表一](../images/消融实验总表-1.png)

![消融实验总表二](../images/消融实验总表-2.png)

总表适合回答:

- 每项核心贡献是否必要
- 各项贡献的收益大小
- 完整方法是否由多项贡献共同构成

### 模块内部小表

对一个模块的表示方式, 超参数或替代设计分别验证

![消融实验模块表](../images/消融实验模块表.png)

![消融实验设计选择表](../images/消融实验设计选择表.png)

小表可以检查:

- 表示方法选择
- 超参数敏感性
- 输入数据质量敏感性
- 损失项和训练策略
- 模块交互
- 速度和精度的权衡

## 困难场景和演示

- 选择下游研究群体真正关心的场景
- 在更复杂, 更稀疏, 更嘈杂或约束更严格的数据上测试
- 展示方法上限, 不是只寻找容易成功的样本
- 报告典型失败情况和适用边界
- 可交互演示适合展示连续输入, 参数变化和真实使用过程

## 图表说明

图表说明至少包含:

- 数据集或场景
- 训练和测试设置
- 指标与方向
- 符号和缩写
- 公平比较所需的特殊条件

结果讨论放在正文, 图表说明只在必要时用一句话概括最主要发现

## 实验严谨性检查

- 基线是否足够强且足够新
- 是否遗漏领域标准指标
- 每项核心设计是否有消融
- 不同方法是否采用公平协议
- 摘要和引言中的数值是否与表格一致
- 是否只报告成功结果而隐藏失败条件
- 是否明确评价范围和数据边界

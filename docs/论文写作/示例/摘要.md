# 摘要示例

## 版本一: 技术问题 -> 技术贡献

适用于核心贡献比较集中, 不需要单独解释核心认知的论文

```tex
\section{Abstract}
% 说明任务和输入输出
% 说明已有方法无法解决的技术问题及其原因
% 用一到两句话介绍解决问题的技术贡献
% 说明技术贡献带来的优势
% 说明有实验支持的主要结果
```

句子职责:

1. 任务句: 让读者知道研究对象和目标
2. 问题句: 指出已有方法在目标设置下为什么失效
3. 贡献句: 给出方法名称和核心做法
4. 优势句: 解释该做法怎样改变问题结构
5. 结果句: 只写已有实验支持的结果

注意:

- 贡献句不需要展开每个模块
- 新方法名称第一次出现时必须能从上下文理解
- 不要从问题句直接跳到读者从未见过的新名词

## 版本二: 技术问题 -> 核心认知 -> 技术贡献

适用于方法建立在一个容易解释且有价值的核心认知上

```tex
\section{Abstract}
% 任务
% 已有方法的技术问题和技术原因
% 一句话说明解决问题的核心认知
% 一到两句话说明怎样把核心认知实现为方法
% 技术优势和新知识
% 实验结果
```

通用表达骨架:

```text
This work studies [task] under [setting]
Existing methods rely on [assumption], which causes [failure] when [condition]
Our key observation is that [observation]
Based on this observation, we propose [method] that [core mechanism]
This design enables [advantage]
Experiments on [datasets / settings] show [supported result]
```

检查核心认知是否有用:

- 它是否直接解释目标技术问题
- 它是否能够推导出方法设计
- 没有后续方法句时, 读者是否仍然理解它的含义
- 它是否只是把方法步骤换了一种抽象说法

## 版本三: 多项贡献 -> 分别说明优势

适用于贡献之间相对独立, 每项贡献都需要单独说明价值的论文

```tex
\section{Abstract}
% 任务和必要的问题背景
% 贡献一以及它的技术优势
% 贡献二以及它的技术优势
% 贡献三以及它的技术优势
% 实验结果
```

每项贡献尽量用一个完整关系表达:

```text
We introduce [contribution], which [mechanism and advantage]
```

不要把摘要写成没有因果关系的模块名称列表

## 结果句

结果句可以包含:

- 主要数据集和任务设置
- 与强基线相比的主要提升
- 鲁棒性, 效率或泛化等关键结论

结果句不应包含:

- 尚未完成的实验
- 没有公平比较支撑的最佳水平声明
- 只在个别样本成立的泛化结论
- 正文没有解释的额外主张

## 自检

- 一遍阅读后能否识别任务, 问题, 贡献和结果
- 技术问题是否正好是方法解决的问题
- 技术原因是否明确
- 方法名称和新术语是否信息自足
- 每个强主张是否能指向具体实验
- 是否有一句话同时承担过多职责

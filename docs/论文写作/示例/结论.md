# 结论示例

## 基本结构

```tex
\section{Conclusion}
% 本文解决的问题
% 核心方法和核心认知
% 最有代表性的实验证据
% 实际价值或新知识
% 局限和后续方向
```

通用骨架:

```text
This work addresses [problem] by introducing [method]
The key idea is [insight], which enables [main advantage]
Experiments across [datasets / settings] support [main conclusion]
A current limitation is [scope boundary]
Extending the method to [future setting] is an important direction
```

## 怎样写局限

优先讨论由任务目标或问题设置造成的范围边界:

- 只处理较短序列
- 依赖受控视角或已知相机
- 只在特定传感器或数据分布下验证
- 计算或存储成本限制实际部署范围

局限需要具体说明:

- 当前方法在哪个条件下受限
- 该限制是否与当前同类方法共同存在
- 它影响哪些应用
- 后续工作需要改变什么

## 技术缺陷与范围局限

### 技术缺陷

- 在关键指标上明显弱于强基线
- 为改善一个指标而严重损害另一个重要指标
- 方法依赖不合理假设
- 需要每个场景单独调整参数
- 新设计带来的代价大于收益

### 范围局限

- 当前任务设置本身限制了评价范围
- 与相同设置下的当前方法相比仍有竞争力
- 扩展到更广范围需要新的研究

不能只根据名称判断, 需要结合强基线, 任务目标和实际权衡

## 示例

过度包装:

```text
Our method is currently limited to short sequences, which can be easily solved in future work
```

问题:

- 没有说明为什么受限
- 没有说明与已有方法的关系
- `easily solved` 没有证据

更可信的结构:

```text
The current evaluation focuses on sequences of [range] because [technical or data reason]
This setting is comparable to [current scope], but it limits applications involving [longer / harder setting]
Extending the representation to [future direction] remains an important problem
```

## 自检

- 是否重新回答了论文解决什么问题
- 是否总结了核心认知而不是重复摘要
- 是否引用了最关键的实验证据
- 局限是否具体且可信
- 是否把严重缺陷包装成普通后续工作
- 后续方向是否由局限自然推出
- 是否在结论中新增正文没有支持的主张
